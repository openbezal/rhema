# Unambiguous typed references and preview ownership

This #138 slice builds independently on our preference restore draft #204. Quick search prefers exact installed book names/abbreviations, then accepts a prefix only when it identifies one canonical book number. An ambiguous `J` or ordinal does not guess by database order. Numeric, Roman and written ordinals remain equivalent, without confusing II and III. Unicode labels use canonical normalization. `JA 2 2`, `ja 2:2` and `Ja 2.2` resolve to James 2:2 when James is the unique installed match. Zero coordinates and repeated delimiters are rejected.

Typing a delimiter completes a unique book/chapter; pasting a complete alias canonicalizes the displayed reference. Tab/Right still advance completion and Enter explicitly presents. Deletion, editing in the middle and IME composition are not rewritten. The input placeholder no longer promises that the ambiguous prefix J means John. These are frontend reference controls; no speech parsing or database labels change.

Only a new edit or explicit acceptance owns typed navigation. Translation/catalog refreshes can update suggestions without replaying old input. With John 3:16 retained in Search, manually selecting John 3:18 and switching languages keeps 3:18 in preview and the program frame. Chapter loads check request order, translation, current chapter and selection ownership. Quick dropdowns match their current query/translation and hide previous rows while a newer lookup waits. Context results check the current translation and become stale as soon as a newer query is entered, before its debounce fires. The maintenance guards from #204 remain in place.

Typed requests now carry their originating translation and selection through the shared navigation controller. The controller cancels a typed request synchronously when translation or selection ownership changes. Browser artifacts cover the reviewed behavior; these post-review fixes have automated evidence. No second review was requested.
