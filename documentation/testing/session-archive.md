# Session archives and saved references

This independent #140 slice builds on our atomic document draft #201. The Session button in the transport bar opens a right-hand drawer with current-session exports and a separate saved-reference view. It adds session JSON, final transcript TXT, and portable preferences JSON. It can read version 1 session/preferences documents for reference. Applying preferences, machine mapping, new-session reset and complete service-event journaling are subsequent work; this does not complete #140 or close an issue.

## Data contract

Session JSON contains completed transcript segments in their current order, the current Queue with source text/identity, retained detections and bounded quotation history, and portable preferences/custom themes. Detections are explicitly labeled `current-snapshot`; earlier dismissed/expired results are not recovered. Partial transcript, words/provider internals, live content/runtime state, provider API-key fields, audio-device identifiers, output/monitor mappings and onboarding state are excluded. Preferences-only export omits session content entirely. Source translation codes take precedence over numeric database IDs; absent attribution is preserved as unknown. No active translation is guessed for unknown historical text.

The snapshot is captured, normalized and validated before waiting for a file dialog. JSON uses a versioned discriminator and bounded schemas, including every theme field. Unknown object fields are stripped at every schema level; nonfinite/out-of-range data, unknown versions, malformed JSON and oversized UTF-8 text reject before returning an opened document. Zod 3.25.76 is a direct pinned dependency already present in the lockfile; no package version was upgraded. Native #201 remains the final 64 MiB file-size and atomic-write boundary. Transcript-only export validates its own data and remains available even if an unrelated saved theme is invalid.

Opening a document only replaces the drawer's saved-reference value after the complete document validates. It does not mutate current transcript, Queue, language selection, themes, detection state or Live. A failed or cancelled subsequent open preserves the previous reference. Save/open cancellation, errors and successful native receipts have distinct messages. Historical text is rendered as text, without creating presentation actions or automatically loading theme images. Reference rows initially render in groups of 100 with progressive disclosure; long text can be expanded.

## Verification

The test-first schema, file-consumer and real Sheet interaction suites cover Unicode, final-only transcript, exact TXT output, portable whitelist/unknown-key stripping, stable source identity, unknown attribution, detached snapshots, compatibility with every built-in theme copied to a custom theme, score provenance, empty data, malformed/future versions, nested invalid themes/coordinates, size bounds, native cancellation/errors, independent transcript capture, import isolation, preservation of the previous archive, pending-action guards, friendly version feedback and keyboard focus restoration. Radix restores focus asynchronously; the test awaits the real focus state rather than assuming synchronous teardown.

The complete saved portable settings grid is covered by a mounted regression and a final production-browser follow-up, including gain, threshold/cooldown, quotation retention/capacity, Follow and both automation preferences. See [saved preferences](assets/session-archive-preferences-minimum.png).

One whole-branch review found that normal editor-created empty image placeholders blocked JSON exports. Both session and preferences export regressions failed before the fix and now preserve active/inactive background, plate, verse, reference and secondary placeholders. Nonempty non-image URL rejection remains covered. The same fix pass makes export errors direct the operator to Theme Designer rather than asking them to choose an imported file. No second review was requested. Earlier browser evidence covers unchanged layout/workflows; these post-review cases use real capture/schema/store code with native file I/O mocked.

The browser fixture uses the actual production App/components/CSS at **1024×600**, with native file I/O, database, audio and output boundaries mocked. It never captures a microphone, contacts a transcription provider, writes a real exported file or starts a physical output. Browser evidence verifies all three export formats, exclusion of a fake credential and unfinished partial, Unicode, progressive transcript rendering from 100 to 200 to all 205 segments, source-attributed saved Queue, preserved current Live/Queue/transcript, read/write cancellation/errors, future/malformed files, light/dark display, typing guards, Tab and close/Escape focus recovery. No browser console warnings/errors were recorded. These do not establish native dialog or installed-package acceptance.

## Remaining acceptance

Run packaged native dialogs on macOS, Windows and Linux: actual cancellation/overwrite prompt, path handling, writable/unwritable destinations, exact exported bytes and a save/open round trip. Verify multiple-hour real transcript/queue workflows with representative custom themes and image/font availability on a second PC. Preference restoration must stage and validate mappings before changing active/persisted state; failure must preserve the previous profile. New-session reset must cancel stale frontend/native work across a stopped session boundary. These are separate acceptance tasks and are not inferred from the browser mocks or passing CI.
